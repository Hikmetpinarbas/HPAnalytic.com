# Security reporting

This repository is publicly readable. Do not open a public issue that contains a vulnerability, credentials, personal data or unreleased editorial material.

Report security findings privately to the repository owner. Include the affected revision, a minimal non-secret reproduction, severity and suggested containment. Never send tokens, keys or raw private data.

Treat the private editorial studio, phone/Termux adapters and production deployment credentials as separate trust boundaries. Changes to authentication, `/control` routes, deployment or secret handling need explicit authorization and independent review.

Automated security checks here are supporting evidence, not a substitute for a threat model or rights audit.
